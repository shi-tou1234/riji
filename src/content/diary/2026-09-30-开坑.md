主博客已经 900 多次提交、50 多篇文章、12 个模型轮番上阵。前台能跑，后台能传，搜索有，地图有，评论有，Electron 客户端也有。

功能是够了。就是有点重。

## 这次想试试相反的路

不是把功能砍到刚好能用，而是砍到只剩「写」和「读」。

| | 主博客 | 开发日记 |
| --- | --- | --- |
| 依赖 | 20+ | 1 |
| 后台 | 有 | 无 |
| 上传方式 | 后台 + GitHub API | 丢 .md 文件 |
| 提交者 | 我手动登录后台 | agent 直接写文件 |

没有登录页，没有富文本编辑器，没有防抖的自动保存。就是 `src/content/diary/` 里一个 Markdown 文件，跑 `pnpm build`，上线。

## 反正写日记这件事本身很简单

一天一篇，或者一件事一篇。日期从文件名和 frontmatter 里读，摘要从首段截，标题用圆体，日期戳用等宽。

配色从羊皮纸换成了松石青。既然是独立站，就别跟主博客长得一模一样——那还不如直接加个分类。字体栈还是老三样：标题楷体、卡片圆体、正文宋体，靠本机字体回退，不拉任何 CDN。

深浅色两套，亮色 `#f2f7f5` 雾白、暗色 `#0f1614` 墨绿，链接色亮色下是青碧 `#0f766e`，暗色下提亮到 `#4fd1c5`，不然在深底上会糊掉。

## 留给以后的部分

- 目录：只有 h2/h3，超过一节才出现
- 代码高亮：Astro 内置的 Shiki 跟着走，不用配
- 没做的：搜索、标签筛选、评论、RSS、统计

后面哪个真的碍事了再加。反正加一个功能的成本，比现在这个站从零搭起来低多了。
